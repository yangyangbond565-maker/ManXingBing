## 3. 数据流

1. generate.py 按固定 seed 生成 7 个 CSV。
2. load_mysql.py 建表并用 LOAD DATA LOCAL INFILE 批量入库。
3. quality_check.py 对 7 表执行 30+ 检查，输出 PASS/FAIL。
4. sync_mysql_to_hive.py 导出 Tab 分隔文件；本次用 webhdfs 模式实际写入 HDFS。
5. Spark 读取 ODS，M1 生成 DWD 临时视图，M2-M8 计算。
6. PySpark 从 HDFS 读取 ODS，将 12 张 ADS 写 HDFS，同时通过 JDBC 写 MySQL ADS。
7. Spring Boot 只读 ADS/业务表，统一 JSON 返回。
8. Vue 3 通过 /api 代理访问后端，ECharts 渲染。
9. Matplotlib 从 MySQL ADS 读取并输出 8 张图。

## 4. 分层设计

### 4.1 ODS
七张外部表，字段与 MySQL 一致，日期用 STRING 保留原始格式，便于溯源。

### 4.2 DWD
patient_clean、checkup_clean、disease_clean、lifestyle_clean、visit_clean、medication_clean、followup_clean。完成去重、范围过滤、分级字段。

### 4.3 ADS
面向展示的宽表/汇总表：overview、patient_profile、disease_dist、severity、comorbidity、risk_factor、visit_analysis、medication_analysis、drug_by_disease、trend、health_score、health_level、data_quality、module_run/kpi。

## 5. 关键设计决策

1. **统计口径单独建表**：ads_overview 明确 total_patients=100000，与七表总行数分开。
2. **分析结果落 MySQL**：前端只依赖 MySQL，避免每次打开页面都启动 Spark。
3. **评分逐患者落表**：ads_health_score 支持分页、筛选、详情，而不是只存聚合。
4. **趋势训练/预测分段**：is_forecast 标记，API 同时返回历史拟合和未来预测。
5. **数据质量独立表**：ads_data_quality 来自 quality_check.py，不让 Spark 自证。
6. **Windows 兼容回退**：Spark 直接读单个 TSV 文件（不做目录 listStatus），结果走 JDBC，规避 ACL/目录写入限制。

## 6. 部署拓扑

- 开发：Windows + MySQL + Spark local[4] + Spring Boot + Vite preview。
- 大数据环境：VMware CentOS 7（4 vCPU / 8 GB，IP 192.168.20.135）+ HDFS 3.3.6 + Hive 3.1.3 + Spark 3.3.4 + MySQL 8.0（Windows）。
- 生产化需增加：YARN、HiveServer2、Sqoop、Nginx、HTTPS、权限、监控。

## 7. 与原文架构的差异

| 项 | 原文 | 本项目 | 原因 |
|---|---|---|---|
| 后端 | Spark Java 任务 + 单接口 | Spring Boot 只读 API + 14 接口 | 验收要求前后端真实联调 |
| 结果存储 | HDFS 为主 | HDFS ADS + MySQL ADS | 双写：HDFS 满足数仓要求，MySQL 支持稳定查询 |
| 预测 | Spark SQL 线性回归 | Python 计算最小二乘 + Spark SQL 结果表 | 与原文算法一致，便于输出 R² |
| 前端 | 单页 Dashboard | 管理台 + 大屏 + 9 页 | 验收要求完整管理平台 |
